# Тест-кейсы: Vue-компоненты кабинета/сайта

Список проверяемых сценариев для `assets/vue/Cabinet/`. При добавлении
нового кейса — дописывайте сюда строку с методом, где он проверяется.

Отдельного модуля `Public` больше нет — шаблон кабинета (`templates/cabinet/base.html.twig`)
используется для всего сайта (доступен и неавторизованным посетителям, пункты
меню, требующие входа, скрыты через `is_granted('ROLE_USER')`). Каталог игр,
витрина своих игр, вход и регистрация физически живут в `Controller/Cabinet`
и `assets/vue/Cabinet`, хотя доступны без авторизации.

## GameDetail.spec.js

Тэйки видны всем, но кнопка "Добавить тэйк" показывается только при
`isAuthenticated: true` (проп из Twig, `is_granted('ROLE_USER')`) — иначе
вместо неё ссылка на `/login`. `mountGameDetail()` по умолчанию монтирует
с `isAuthenticated: true`, чтобы не дублировать проп в каждом тесте.

| Кейс | Метод теста |
|---|---|
| Запрос игры по slug, рендер деталей | `запрашивает игру по slug и рендерит подробности` |
| Состояние ошибки загрузки игры | `показывает ошибку, если игра не найдена` |
| Список тэйков игры загружается через `GET /api/takes?filters[game]=<id>` и рендерится | `загружает и показывает список тэйков игры` |
| Пустое состояние, если тэйков нет | `показывает пустое состояние, если тэйков ещё нет` |
| Кнопка "Добавить тэйк" открывает модалку `TakeCreateModal` | `кнопка "Добавить тэйк" открывает модалку создания` |
| Событие `created` от модалки добавляет тэйк в начало списка и закрывает модалку | `добавляет созданный тэйк в начало списка и закрывает модалку` |
| Без `isAuthenticated` — кнопка скрыта, вместо неё ссылка на `/login` | `без isAuthenticated кнопка "Добавить тэйк" скрыта, вместо неё ссылка на вход` |

## OurGameDetail.spec.js

Раскладка: слева от скриншотов — системная информация (без описания),
описание — под скриншотами на всю ширину (см. `.our-game-detail__body`
в `assets/styles/public/our-game.css`). Блок "Посты" — карточки с картинкой
слева, типом/заголовком/описанием справа; описание — HTML из редактора
в админке, санитизируется через DOMPurify перед `v-html`. Модалка поста —
класс `.our-game-post-modal` (70vw).

| Кейс | Метод теста |
|---|---|
| Запрос `GET /api/our-games/{slug}`, баннер, `document.title`, системная инфа расположена перед скриншотами в DOM | `запрашивает игру у публичного API, показывает баннер и системную инфу слева от скриншотов` |
| Описание — под скриншотами, не в боковом блоке | `описание отображается под скриншотами, а не в боковом блоке` |
| Состояние ошибки загрузки | `показывает ошибку при неудачном запросе` |
| Без баннера — используется обложка, без обложки и баннера — плейсхолдер | `без баннера использует обложку, без обложки — плейсхолдер` |
| Клик по скриншоту открывает лайтбокс | `рендерит скриншоты и открывает лайтбокс по клику` |
| Блок "Скачать" — ссылка с подписью платформы | `показывает ссылку на скачивание с подписью платформы` |
| Ссылка на трейлер, если задана | `показывает ссылку на трейлер, если она задана` |
| Блок "Посты" — запрос `filters[game]={id}`, карточка с заголовком и HTML-описанием (жирный текст рендерится как `<strong>`) | `запрашивает опубликованные посты по игре и рендерит карточки с заголовком и HTML-описанием` |
| Блок "Посты" — пустое состояние | `показывает сообщение, если постов ещё нет` |
| Клик по карточке — широкая модалка (`.our-game-post-modal`) с заголовком и полным HTML-описанием (`GET /api/our-game-posts/{id}`) | `клик по карточке открывает широкую модалку с заголовком и полным описанием поста` |
| Пост типа `major_update` получает класс `.our-game-post-card--major` (подсветка), остальные — нет | `пост о крупном обновлении выделяется классом --major` |
| `<script>` в HTML-описании поста вырезается DOMPurify перед рендером | `санитизирует HTML в описании поста (убирает script)` |
| Закрытие модалки поста по крестику | `закрывает модалку по клику на крестик` |

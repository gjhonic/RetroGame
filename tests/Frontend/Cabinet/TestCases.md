# Тест-кейсы: Vue-компоненты кабинета/сайта

Список проверяемых сценариев для `assets/vue/Cabinet/`. При добавлении
нового кейса — дописывайте сюда строку с методом, где он проверяется.

Отдельного модуля `Public` больше нет — шаблон кабинета (`templates/cabinet/base.html.twig`)
используется для всего сайта (доступен и неавторизованным посетителям, пункты
меню, требующие входа, скрыты через `is_granted('ROLE_USER')`). Каталог игр,
витрина своих игр, вход и регистрация физически живут в `Controller/Cabinet`
и `assets/vue/Cabinet`, хотя доступны без авторизации.

## Profile.spec.js

Единственный способ посмотреть профиль — публичная страница `/profile/{nickname}`
(`templates/cabinet/profile/show.html.twig`, доступна без авторизации, `nickname`
всегда обязательный проп). Отдельной страницы `/cabinet/profile` больше нет —
свой профиль открывается по той же ссылке `/profile/{ownNickname}` (см. сайдбар
в `templates/cabinet/base.html.twig`), самому себе он виден, даже если закрыт
настройками приватности (это уже проверяется в `ProfileVisibilityServiceTest`,
здесь не дублируется).

Шапка — аватар слева (переиспользует `.avatar-upload__image`/`.avatar-upload__placeholder`
из `AvatarUpload.vue`, инициал берётся из ника — email в публичном API больше
не отдаётся), ник/девиз-заглушка справа, плюс два блока-витрины: "Любимые игры"
(`GET /api/profile/{nickname}/favorites`) и "Сейчас прохожу"
(`GET /api/profile/{nickname}/games?status=in_progress`) — сетки обложек
`.profile-game-tile`, каждая ссылка ведёт на `/games/{slug}`. Три запроса идут
последовательно при монтировании: профиль → избранное → статус (`mountProfile()`
мокает их в этом порядке). Редактирование ника/аватара — отдельные компоненты
на `/cabinet/settings` (`NicknameForm.vue`/`AvatarUpload.vue`).

| Кейс | Метод теста |
|---|---|
| Запрос профиля по нику, рендер ника | `запрашивает профиль по нику и рендерит ник` |
| Без аватара — инициал ника (заглавная буква) | `без аватара показывает инициал ника` |
| Ошибка загрузки профиля | `показывает ошибку при неудачном запросе профиля` |
| `404` от публичного API (закрыт/не существует) — сообщение, без лишних запросов | `закрытый или несуществующий профиль (404) показывает сообщение и не запрашивает игры` |
| Любимые игры: запрос и карточки со ссылкой на игру | `запрашивает /api/profile/{nickname}/favorites и рендерит карточки` |
| Любимые игры: пустое состояние | `показывает пустое состояние, если любимых игр нет` |
| Любимые игры: ошибка запроса не ломает остальную страницу | `показывает ошибку, если запрос не удался` |
| "Сейчас прохожу": запрос с `status=in_progress`, карточки | `запрашивает /api/profile/{nickname}/games?status=in_progress и рендерит карточки` |
| "Сейчас прохожу": пустое состояние | `показывает пустое состояние, если сейчас ничего не проходит` |
| "Сейчас прохожу": ошибка запроса | `показывает ошибку, если запрос не удался` |
| Блок подписки: счётчики `.profile-header__followers`/`.profile-header__following` + кнопка "Подписаться" (`.profile-header__follow-toggle`) | `показывает счётчики подписчиков/подписок и кнопку "Подписаться"` |
| Клик "Подписаться" → `PUT /api/cabinet/users/{nickname}/follow`, кнопка переключается на "Отписаться" | `клик по "Подписаться" отправляет PUT и переключает кнопку на "Отписаться"` |
| Клик "Отписаться" → `DELETE /api/cabinet/users/{nickname}/follow` | `клик по "Отписаться" отправляет DELETE` |
| Гость вместо кнопки видит ссылку `/login` (тот же класс `.profile-header__follow-toggle`, но `<a>`) | `для неавторизованного посетителя вместо кнопки — ссылка на вход` |
| На своём профиле (`isOwnProfile: true`) счётчики видны, кнопки подписки нет | `на своём профиле показываются счётчики, но не кнопка подписки` |

Модалки подписчиков/подписок — общий компонент `ConnectionsModal.vue`,
общее состояние/пагинация — фабрика `createConnectionsList()` внутри
`Profile.vue` (один и тот же паттерн накопления страниц, что и в
`TakeFeed.vue`), обёрнута в `reactive()` — иначе вложенные `ref` не
разворачиваются при чтении через `connections.xxx` в шаблоне дочернего
компонента (см. комментарий в коде). Классы теперь общие: `.connection-item`,
`.connections-list`, `.connections-load-more` (раньше — `.follower-item`/
`.followers-list`/`.followers-load-more`, переименованы при добавлении
списка подписок). Модалка подписчиков открывается кликом по
`.profile-header__followers`, подписок — по `.profile-header__following`;
каждая грузится один раз и кэшируется в памяти отдельно друг от друга —
повторное открытие после закрытия не шлёт новый запрос.

| Кейс | Метод теста |
|---|---|
| Клик по счётчику подписчиков → `GET /api/profile/{nickname}/followers?page=1`, ники со ссылкой на `/profile/{nickname}` | `клик по счётчику подписчиков запрашивает список и показывает ники со ссылкой на профиль` |
| Подписчик без ника (может подписаться, даже не заведя себе ник) — без ссылки, плейсхолдер "Игрок"/"?" вместо `null.slice()` | `подписчик без ника (только аватар) отображается без ссылки и с плейсхолдером "Игрок"` |
| Пустой список подписчиков | `показывает пустое состояние, если подписчиков нет` |
| Ошибка загрузки списка подписчиков | `показывает ошибку при неудачном запросе` |
| Несколько страниц → "Загрузить ещё" подгружает `page=2`; повторное открытие модалки не перезапрашивает список | `при нескольких страницах "Загрузить ещё" подгружает следующую и не запрашивает список повторно при переоткрытии` |
| Закрытие по клику на крестик | `закрывается по клику на крестик` |
| Клик по счётчику подписок → `GET /api/profile/{nickname}/following?page=1`, независимая от подписчиков модалка (открыт только один `.modal-overlay`) | `клик по счётчику подписок запрашивает /following и показывает список независимо от подписчиков` |
| Пустой список подписок | `показывает пустое состояние, если подписок нет` |

## NicknameForm.spec.js

Группа "Ник" на `/cabinet/settings` (`.cabinet-panel`, тот же стиль, что и
`PasswordChangeForm.vue`) — единственное место, где можно задать/сменить
ник (нужен, чтобы вообще иметь `/profile/{nickname}`). `GET /api/cabinet/profile`
для начального значения, `PATCH /api/cabinet/profile/nickname` при сабмите
формы; `422` с `errors.nickname` (например, "уже занят") показывается под
полем, как и в `TakeCreateModal.vue`.

| Кейс | Метод теста |
|---|---|
| Запрос текущего ника, подстановка в поле и подсказку `/profile/{nickname}` | `запрашивает текущий ник и подставляет его в поле и подсказку` |
| Без ника подсказка показывает многоточие вместо `/profile/null` | `без ника подсказка показывает многоточие` |
| Ошибка загрузки настроек | `показывает ошибку при неудачном запросе настроек` |
| Валидная отправка → `PATCH /api/cabinet/profile/nickname`, сообщение об успехе | `отправляет новый ник и показывает сообщение об успехе` |
| Ник уже занят (`422`) → ошибка под полем | `показывает ошибку по полю, если ник уже занят` |
| Сетевой сбой → общая ошибка | `показывает общую ошибку при сетевом сбое` |

## ProfilePrivacyForm.spec.js

Группа "Приватность" на `/cabinet/settings` (`.cabinet-panel`, тот же стиль,
что и `PasswordChangeForm.vue`) — переключатель открытый/закрытый профиль,
`GET /api/cabinet/profile` для начального значения (`isProfilePublic`,
плюс подставляет `nickname` в текст подсказки "/profile/{nickname}"),
`PATCH /api/cabinet/profile/privacy` при переключении радио-кнопки.

| Кейс | Метод теста |
|---|---|
| Запрос текущих настроек, по умолчанию отмечен закрытый профиль | `запрашивает текущие настройки и отмечает закрытый профиль по умолчанию` |
| Если профиль уже открыт — отмечена соответствующая радио-кнопка | `отмечает открытый профиль, если он уже открыт` |
| Ошибка загрузки настроек | `показывает ошибку при неудачном запросе настроек` |
| Выбор "Открытый профиль" → `PATCH /api/cabinet/profile/privacy`, сообщение об успехе | `выбор "Открытый профиль" отправляет PATCH и показывает сообщение об успехе` |
| Сетевой сбой при сохранении → общая ошибка | `показывает общую ошибку при сетевом сбое во время сохранения` |

## GameDetail.spec.js

Тэйки видны всем, но кнопка "Добавить тэйк" показывается только при
`isAuthenticated: true` (проп из Twig, `is_granted('ROLE_USER')`) — иначе
вместо неё ссылка на `/login`. `mountGameDetail()` по умолчанию монтирует
с `isAuthenticated: true`, чтобы не дублировать проп в каждом тесте.
Разметка/логика самой карточки тэйка (реакции, комментарии, ник автора —
ссылка на `/profile/{nickname}` при наличии ника) вынесена в `TakeCard.vue` —
здесь она проверяется опосредованно через `GameDetail`, без `show-game`
(одна игра на странице, ссылка на игру не нужна); тот же компонент с
`show-game` используется в общей ленте, см. `TakeFeed.spec.js`.
Тэйк и сама игра используют один и тот же CSS-класс `.take-reaction` для
кнопок лайка/дизлайка (общий стиль), поэтому в тестах на реакции тэйка
селектор скопирован до `.take-card` через хелпер `takeCardReactions()`, а
в тестах на реакции игры — до `.game-actions` (иначе `findAll('.take-reaction')`
подхватывает оба набора кнопок сразу и ломает индексацию).
Скриншоты — виджет карусели `.screenshot-carousel` (одно большое фото +
стрелки при `screenshotUrls.length > 1` + точки-индикаторы), а не сетка
миниатюр; клик по фото открывает уже существующий полноэкранный `.lightbox`.
Под каруселью — блок `.game-actions`: лайк/дизлайк игры, избранное
(`.game-actions__favorite`) и статус прохождения (`select#playthroughStatus`,
`planned`/`in_progress`/`completed`/`dropped`, пустое значение = снять статус).

| Кейс | Метод теста |
|---|---|
| Запрос игры по slug, рендер деталей | `запрашивает игру по slug и рендерит подробности` |
| Состояние ошибки загрузки игры | `показывает ошибку, если игра не найдена` |
| Список тэйков игры загружается через `GET /api/takes?filters[game]=<id>` и рендерится | `загружает и показывает список тэйков игры` |
| Ник автора тэйка (`.take-card__author`) — ссылка `<a>` на `/profile/{nickname}` | `ник автора тэйка ссылается на его публичный профиль` |
| Автор без ника — `<span>` "Игрок", без ссылки | `без ника автор тэйка отображается как "Игрок" без ссылки` |
| Пустое состояние, если тэйков нет | `показывает пустое состояние, если тэйков ещё нет` |
| Кнопка "Добавить тэйк" открывает модалку `TakeCreateModal` | `кнопка "Добавить тэйк" открывает модалку создания` |

| Без `isAuthenticated` — кнопки лайк/дизлайк тэйка отключены (`disabled`) | `кнопки лайк/дизлайк тэйка отключены для анонимного посетителя` |
| Клик по лайку → `PUT /api/cabinet/takes/{id}/reaction`, счётчик и подсветка обновляются из ответа | `клик по лайку отправляет PUT и обновляет счётчики/подсветку` |
| Повторный клик по уже активной реакции → `DELETE /api/cabinet/takes/{id}/reaction`, подсветка снимается | `повторный клик по уже активной реакции снимает её через DELETE` |
| Клик по счётчику комментариев → `GET /api/takes/{id}/comments`, список рендерится | `клик по счётчику комментариев подгружает и показывает список` |

| Повторный клик по активной реакции игры → `DELETE /api/cabinet/games/{slug}/reaction` | `повторный клик по активной реакции игры снимает её через DELETE` |
| Клик по избранному → `PUT`/`DELETE /api/cabinet/games/{slug}/favorite`, подсветка и текст меняются | `клик по избранному добавляет и убирает игру из избранного` |
